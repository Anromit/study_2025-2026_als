# Введение
Современные локальные сети (LAN) предъявляют высокие требования к надежности, отказоустойчивости и пропускной способности. Две ключевые технологии, позволяющие достичь этих целей при построении коммутируемых сетей Ethernet — это протокол связующего дерева (STP) и агрегирование каналов (Link Aggregation).

Первая решает проблему циклов (петель) в топологии с резервными связями, вторая — увеличивает пропускную способность и резервирует соединения между устройствами. В данном докладе будут подробно рассмотрены принципы работы, версии, настройка и практическое применение этих технологий.

# Часть 1. Протокол STP (Spanning Tree Protocol)
 Проблема петель (Loops) в коммутируемой сети
В отличие от концентраторов, коммутаторы (свитчи) анализируют MAC-адреса и передают кадры только на нужный порт. Однако при наличии избыточных связей возникает проблема:

## Широковещательный шторм (Broadcast Storm) — кадр broadcast бесконечно циркулирует между коммутаторами.

Нестабильность таблицы MAC-адресов — коммутатор постоянно обновляет информацию о том, с какого порта пришел кадр.

Пример: два коммутатора соединены двумя кабелями. Широковещательный кадр от ПК пойдет по одному кабелю, вернется на исходный коммутатор по второму и снова начнет распространяться.

STP решает эту проблему, логически блокируя избыточные порты, оставляя физические резервные линии в «горячем резерве».

## Принцип работы STP (IEEE 802.1D)
Алгоритм STP основан на построении логического дерева без петель.

Основные элементы:

Корневой мост (Root Bridge) — «центр» дерева. Выбирается коммутатор с наименьшим приоритетом и MAC-адресом.

Корневой порт (Root Port — RP) — порт на не-корневом коммутаторе, который имеет наилучший путь к корневому мосту.

Назначенный порт (Designated Port — DP) — порт, который пересылает трафик в каждом сегменте сети. Все порты корневого моста — назначенные.

Заблокированный порт (Alternate / Backup Port) — порт, который находится в состоянии блокировки (не пересылает трафик, но слушает BPDU).

Этапы работы:

Выбор корневого моста — обмен BPDU (Bridge Protocol Data Units).

Определение корневых портов — на каждом не-корневом коммутаторе.

Определение назначенных портов — на каждом сегменте линии связи.

Блокировка остальных портов.

## Состояния портов STP
Процесс согласования проходит через состояния (для избежания временных петель):

Состояние	Характеристика
Disabled	Административно выключен
Blocking	Не передает данные, только слушает BPDU (20 сек.)
Listening	Выбирает роли порта, не учит MAC (15 сек.)
Learning	Учит MAC, но не передает данные (15 сек.)
Forwarding	Нормальная работа (передача данных)
Общее время конвергенции (восстановления при отказе) в классическом STP — до 50 секунд.

## Современные версии STP
Версия	Стандарт	Особенности
STP	IEEE 802.1D (1998)	Медленная конвергенция, один экземпляр дерева на всю сеть.
RSTP (Rapid STP)	IEEE 802.1w	Быстрая конвергенция (менее 6 сек.) за счет активного подтверждения переходов между состояниями.
MSTP (Multiple STP)	IEEE 802.1s	Группирует VLAN в несколько экземпляров деревьев, экономя ресурсы CPU.
В современных сетях (Cisco, Huawei, MikroTik) рекомендуется использовать RSTP или MSTP вместо классического STP.

## Настройка STP (пример для Cisco)
cisco
! Включение RSTP
spanning-tree mode rapid-pvst

! Настройка коммутатора как корневого моста для VLAN 1
spanning-tree vlan 1 root primary

! Изменение приоритета вручную
spanning-tree vlan 1 priority 4096

! Просмотр состояния
show spanning-tree
show spanning-tree vlan 1
1.6 Защитные механизмы STP (STP Security)
BPDU Guard — блокирует порт, если на него приходит BPDU (для портов, подключенных к ПК).

BPDU Filter — игнорирует входящие BPDU и не отправляет свои.

Root Guard — предотвращает захват роли корневого моста чужим коммутатором.

Loop Guard — защита от ошибок, когда порт перестает получать BPDU.

# Агрегирование каналов (Link Aggregation)
## Цели агрегирования
Агрегирование каналов (EtherChannel, LAG, Port Trunking) — объединение нескольких физических портов в один логический канал.

Задачи:

Увеличение пропускной способности — N × скорость одного канала.

Резервирование — при отказе одного физического порта трафик перераспределяется между оставшимися.

Балансировка нагрузки — без необходимости настройки сложных маршрутов.

## Стандарты и протоколы
Протокол	Стандарт	Принцип
LACP (Link Aggregation Control Protocol)	IEEE 802.3ad (802.1AX)	Открытый стандарт. Устройства договариваются о создании агрегированного канала с помощью LACPDU.
PAgP (Port Aggregation Protocol)	Cisco проприетарный	Аналог LACP для оборудования Cisco (устаревает).
Статическое агрегирование	Без протокола	Простое объединение портов вручную (риск петель, если не согласовано).
Рекомендация: использовать LACP как кросс-платформенное решение.

## Условия для объединения портов в LAG
Все порты в группе должны иметь одинаковые параметры:

Скорость и дуплекс (должны совпадать).

Настройки VLAN (native VLAN, разрешенные VLAN).

Настройки STP (порты будут работать как один логический порт).

MTU.

## Алгоритмы балансировки нагрузки (Hashing)
Коммутатор распределяет кадры по физическим каналам на основе хэша от полей заголовка:

Алгоритм	Что учитывает	Особенность
src-mac	MAC-адрес источника	Полезно при обмене с роутером
dst-mac	MAC-адрес назначения	
src-ip	IP-адрес источника	Лучше для L3-коммутации
dst-ip	IP-адрес назначения	
src-dst-ip	Исходный и целевой IP	Самый популярный (сохраняет порядок кадров для потока)
src-dst-port	Порты TCP/UDP	Максимальная детализация
Важно: кадры одного потока (например, TCP-сессии) всегда идут по одному физическому каналу во избежание переупорядочивания.

## Настройка LACP на примере
Cisco:

cisco
interface port-channel 1
 switchport mode trunk
 spanning-tree portfast disable

interface range gigabitethernet 1/0/1-2
 channel-group 1 mode active   ! active — LACP активный
 switchport mode trunk
MikroTik (RouterOS):

text
/interface bonding add name=bond1 mode=802.3ad slaves=ether1,ether2
/interface bridge port add bridge=bridge1 interface=bond1
Проверка:

cisco
show etherchannel summary
show lacp neighbor

## Особенности работы LAG и STP
Для протокола STP агрегированный канал (Port-Channel) выглядит как один порт.

STP блокирует/переводит в forwarding весь LAG целиком, а не отдельные физические члены.

При добавлении/удалении физического порта из LAG дерево STP не перестраивается (конвергенция не требуется).

# Практические сценарии совместного использования STP и LAG
## Типовая топология ЦОД (Data Center)
text
        [Core Switch 1] --- LAG --- [Core Switch 2]
               |                         |
              LAG                       LAG
               |                         |
        [Distr Switch 1] --- LAG --- [Distr Switch 2]
               |                         |
              LAG                       LAG
               |                         |
        [Access Switch 1]           [Access Switch 2]
LAG между уровнями обеспечивает 20-40 Гбит/с.

RSTP / MSTP обеспечивает логическое дерево (обычно один из LAG блокируется для предотвращения петли на уровне L2).

## Резервный LAG с активным STP
При двух соединениях между коммутаторами:

Можно настроить один LAG как активный (в forwarding), второй — как резервный.

STP заблокирует второй LAG, но если первый упадет — RSTP переведет второй в forwarding за секунды.

## Использование MSTP с LAG
MSTP позволяет для разных VLAN использовать разные деревья:

VLAN 10,20 идут через LAG1 (активный), LAG2 — блокирован.

VLAN 30,40 идут через LAG2 (активный), LAG1 — блокирован.

Это повышает утилизацию каналов (не простаивает резерв).

# Типичные ошибки и диагностика
## Ошибки STP
Проблема	Признак	Решение
Петля из-за отключенного STP	Полная остановка сети, broadcast storm	Включить spanning-tree на всех портах
Долгая конвергенция	Потеря пакетов 30-50 сек после отказа	Перейти с STP на RSTP или MSTP
Неверный корневой мост	Трафик идет по длинному пути	Вручную задать root primary
# Ошибки LACP
Проблема	Признак	Решение
Несовпадение настроек VLAN	Порт не входит в LAG, ошибка в логе	Проверить trunk/native VLAN
Разная скорость портов	LAG не поднимается	Использовать одинаковые интерфейсы
Небалансировка нагрузки	Один канал загружен на 100%, другой простаивает	Сменить алгоритм хэширования (например, на src-dst-ip)

Заключение
Протокол STP и агрегирование каналов являются фундаментальными технологиями при построении отказоустойчивых и производительных локальных сетей.

STP (особенно RSTP/MSTP) позволяет создавать резервные топологии без риска петель. Время конвергенции современных версий достаточно мало для большинства корпоративных сценариев.

LACP (Link Aggregation) дает возможность линейно увеличивать пропускную способность и обеспечивает резервирование на физическом уровне без участия более высоких уровней модели OSI.

Грамотное сочетание этих технологий позволяет строить сети уровня предприятий и ЦОД с временем недоступности менее 0.1% в год. При этом администратор должен помнить о защитных механизмах STP (BPDU Guard, Root Guard) и правильной настройке балансировки нагрузки в LAG для эффективного использования всех каналов.
